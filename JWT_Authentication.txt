In all previous sections we have used 2 opaque tokens 
	1. JSESSIONID
	2. CSRF Token
these tokens are stored in cookie. 

* IN opaque tokens - requires a call to auth server or any endpoint to validate and obtain user information. 
* In JWT - This can be validated locally by verifying the token signature using public key, without needing a server call.

* JWT has 3 parts , seperated by "."(period)
	- Header - stores meta infomation related to token. {"alg":"HS256","typ":"JWT"} ===> Encode Base64 ===> eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
	- Payload - {"sub": "1234567890","name": "John Doe","admin": true,"iat": 1516239022} ===> Encode Base64 ===> eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiYWRtaW4iOnRydWUsImlhdCI6MTUxNjIzOTAyMn0
	- Signature(optional) - used to check if the token is tampered or no.  Hash value that is generated based on base64 encoded value of header, body & secret. Secret value in stored in backend just jused to   generate the signature.
